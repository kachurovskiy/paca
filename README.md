# Paca trading terminal

**[Open the app at kachurovskiy.com/paca](https://kachurovskiy.com/paca/)**

A browser-only Alpaca terminal with quotes, candle charts, watchlists, a broad stock scanner, manual orders, portfolio performance, trade history, and supervised paper/live Robots. TypeScript and Preact compile to one HTML file with bundled scripts, styles, and fonts.

Real-time SIP market data access is required. Overnight sessions automatically use BOATS for real-time quotes, trades, and intraday history.

One connected tab owns an account within an origin/browser profile. Manual orders and Robots share one command queue and durable IndexedDB execution records. Robots support Trend, Wick Capture, and VWAP Mean Reversion in paper and live accounts. Live manual trading and Robot entries must be enabled separately for each connection. After a successful connection, the API key, secret and selected environment are saved in this browser's local storage. The app reconnects automatically on each page load using those keys. If connection fails, the connection dialog shows the error and lets you retry or update the keys. **Disconnect** or **Cancel connection** keeps this page disconnected until you reconnect or reload. Choose **Forget saved keys** in the connection dialog to remove them and stop automatic reconnection on future visits.

## Using the workspace

- Terminal: each watchlist row shows the last available 24 hours of prices and their percentage change, including daytime and overnight history. The window ends at the latest recorded price, retaining the most recent trading day over weekends and holidays; hover to see its ending time. Five-minute history refreshes every two minutes, with live trades updating the latest point. Refresh failures retain the last loaded chart. Add/remove symbols, choose chart intervals, toggle EMA/VWAP, and zoom with the wheel. Quote and account refreshes preserve ticket drafts, focus, and the mounted chart.
- Manual trading: the compact ticket shows its environment, order, estimated value, execution settings, spread, quote age, available capital, and position after a full fill. Expand Quote & execution details for bid/ask, reservations, and session explanations. Button bars select order type, duration, and sessions. Defaults are one share, Day, and regular hours. Limit prices prefill from the ask for buys or bid for sells, falling back to the latest price, and follow new quotes until you edit or clear the field. Limit orders can explicitly opt into extended hours, including eligible overnight trading. Choose Day or GTC (broker expiry applies, up to 90 days); fractional closes require Day. Paca submits only while a selected session is open. Enter 1–100,000 whole shares, or sell the full fractional remainder. Add stop loss to a whole-share buy to submit an attached stop that activates after the buy fills completely, or choose Stop when selling existing holdings. Stops use Day or GTC and regular hours only; a triggered stop becomes a market sell, so its fill price can differ from its trigger price. Attached stops remain visible and cancelable in Orders after a reload. Price increments are validated before submission: $0.01 at $1 or above, $0.0001 below $1. Full-holding sells (including stops) and live orders estimated at $10,000 or more or at least 25% of equity require confirmation; smaller trades submit directly. Close holding prepares a limit order with the exact holding quantity for review. Changes to a confirmed order or its consequences require another review. Submitted tickets retain their execution rules until New order. See [Alpaca order restrictions](https://docs.alpaca.markets/us/docs/orders-at-alpaca).
- Scanner: operates 24/5 from Sunday 20:00 through Friday 20:00 New York time on exchange trading dates (holidays excluded). SIP supplies daytime data; BOATS supplies eligible, non-halted overnight stocks. Premarket, regular, after-hours and overnight scans compare volume with the same historical session segment, with fresh bars and quote warmup required after each boundary. Complete REST responses establish omitted extended-session minutes; only reported volume is summed, without inventing candles. Extended-session trends use elapsed time, at least two-thirds of the window's minute bars, no more than two consecutive omitted minutes, and a bar for the latest completed minute. Unverified gaps, incomplete requests and stale quotes cannot qualify. Regular-session bars retain contiguous coverage checks. SIP and BOATS access are required. Discovery ranks the broad eligible liquidity universe and supplements it with movers/activity data. The Candidates tab shows admitted or observed trend candidates; saved reviews retain unavailable evaluations with their actual data status. Inspect a candidate's chart and observations; monitoring, reviewed, and dismissed choices persist in the new namespace.
- Robots: new plans support the full trading day from the prior evening at 20:00 through 20:00 New York time, including premarket, regular, after-hours and overnight sessions. Research opportunities, review the exact plan, approve, inspect, pause/resume, reconcile, or close. Navigation keeps supervision running. Research, outcomes, forecasts, and exports use current-version records. Unknown fees or missing observations remain unavailable; live fills, paper fills, and sparse Trend simulations remain separately labeled.
- Performance and history: inspect equity, monthly/daily/ticker results, actual fills, ended runs, and JSON exports. Incomplete imports and unmatched fills are explicit. History reconstruction reports matched long stock results before fees; run accounting separately reports fee completeness.
- API activity: the footer shows Trading API and Market Data API HTTP attempts in the rolling last 60 seconds. Click the counts for endpoint/method totals, retries, response statuses, failures and average duration. Counts include pagination and failed attempts from this connection, update each second, and exclude WebSocket messages. Credentials, request bodies and order identifiers are not recorded.

Robot supervision keeps its five-second cycle while sharing account order batches (including attached stops after their entries fill), using fresh streamed quotes, and sharing asset/calendar reads for 20/60 seconds. Wick needs no bar requests. Strategies that use five-minute bars load history once, refresh overlapping completed bars at the next five-minute boundary with a five-second grace, and reload the full window every 15 minutes for historical revisions. Scanner subscription changes retain fresh observations and caches but gate decisions until acknowledgement; disconnects and feed changes invalidate execution data caches. Missing orders still require direct broker lookups; every order-changing action retains fresh account and quote checks. Broker order/fill timestamps are projected into millisecond UTC for strategy decisions, including recovered holding clocks; journals retain the original broker precision.

Manual orders also share the account order batch. Accounts without active Robots or working orders refresh their display every 15 seconds (20 baseline Trading API requests per minute); supervised accounts retain the five-second cycle (60 baseline requests per minute). Each account observation reads the account, positions, clock, open orders and recent closed orders; asset/calendar reads, fill recovery and order actions add to those baselines. Explicit reconciliation and order submissions read fresh account state immediately. Research shows exhausted capital and stress budgets in dollars; selecting a strategy does not bypass those allocation limits.

Research refreshes selected symbols in one quote batch before sizing so simulation time does not age out the discovery prices. Failed or limited strategies remain visible in the results. A timed-out VWAP experiment can continue with identical history, parameters and policy; other recorded experiments still count toward holdout exposure. Completed research rejections remain cached.

New Robot proposals target **10% of account equity per run**: $1,000 for a $10,000 account or $10,000 for a $100,000 account, before other limits. Cash and buying power after commitments, existing exposure, 20% per-symbol concentration, 80% aggregate exposure and observed liquidity can reduce the ceiling. Stress-sizing allowances also scale with equity (2% per run, 20% aggregate); existing exposure retains its full-capital stress bound. Proposals display their share of equity and explain binding limits in allocation details. These are sizing rules, not loss guarantees. Research takes a fresh account snapshot, and approval and order submission recheck funds. Existing approved runs retain their frozen ceilings; research new proposals to use the new sizing policy.

To use live Robots, connect with Live selected, open Robots, research opportunities, and enable **Live Robot entries for this connection**. Review a proposal’s capital ceiling, risk budget, parameters, and limitations, then choose **Approve live plan**. Manual live arming does not enable Robots.

Turning Robot entries off blocks new buys and asks running strategies to cancel working entry orders on their next cycle. Those orders can fill until the broker confirms cancellation. Approved runs continue managing exits; Pause stops a run’s supervision and retains its holdings, while Close works toward a confirmed flat position. Reconnecting resets live arming and restores active runs paused; enable entries and explicitly Resume, or use Close without enabling entries.

Regular-hours Robot entries include an Alpaca OTO **GTC sell stop**, submitted atomically with the entry. Outside regular hours, new 24/5 plans use **Day limit orders with extended hours enabled**; Alpaca does not support attached stops in those sessions. After a confirmed extended-hours fill (and cancellation of any remainder), the supervising browser attaches a separate GTC stop. There is no broker stop until that submission is confirmed. Outside regular hours, observed stop triggers and strategy exits use supervised limit sells, which may remain unfilled. Overnight eligibility and fresh BOATS quotes are required; extended-hours capital checks use Reg T buying power. Its fixed backup price uses the tighter of the strategy stop percentage (when present) and the approved run loss trigger, measured from the entry reference price and rounded down to a supported price increment. This reference is not a guaranteed fill price. No unprotected entry is retried if the protected order is rejected or its acknowledgement is uncertain. Broker-held active stops survive Pause, disconnect and browser closure. Robots reconcile their attached stop fills, including fills while offline, as owned executions.

Alpaca activates an attached stop only after the entry fills completely. Partial fills remain exposed until then. While supervised, Robots cancel partial entry remainders and wait for confirmed cancellation before attaching a standalone stop to the confirmed whole-share holding. The run shows whether its stop is active, pending or unconfirmed. A paused run whose stop was canceled or rejected can use **Attach broker stop** without enabling live entries; fractional holdings cannot receive GTC protection and must be resolved explicitly.

Execution records require `paca-snapshots-2`, including explicit exit state and a recorded stop on every regular-hours Robot entry. Standalone extended-hours limit entries are allowed only by an explicitly approved 24/5 plan. Earlier formats are rejected without migration; incompatible active runs or manual commands hold execution and their records remain intact. Before using fresh execution storage, resolve earlier-version runs and outstanding orders through that version or Alpaca. Clearing browser storage does not cancel broker orders or close positions.

Approved session deadlines still apply; existing regular-hours plans retain their original horizons. Research parameters fitted to regular-hours simulations do not validate extended-hours performance, and 24/5 counterfactual fills are not reported as regular-hours simulations.

Robots still require browser supervision for strategy exits, trailing stops, partial fills and the session deadline. Close and strategy exits cancel the broker stop, wait for confirmed cancellation, recheck inventory, then sell; a browser failure during that transition can leave the position unprotected. Reopening retains the exit intent but requires explicit Resume or Close. A stop is retained when current data or the market session prevents an immediate exit. Working GTC entries can fill after the plan ends if the browser is unavailable. Stops trigger only during regular market hours, can slip, and are subject to Alpaca's expiration/corporate-action rules. Check and manage remaining orders directly in Alpaca if supervision is interrupted. See [Alpaca order behavior](https://docs.alpaca.markets/us/docs/orders-at-alpaca).

Live results and forecasts use only the matching account and environment, and paper or simulated outcomes do not establish live performance.

## Run and build

Requires Node.js 22 or newer and npm.

```sh
npm ci
npm run dev
```

Open `http://127.0.0.1:5173`.

```sh
npm test          # Mocked unit tests; no credentials needed
npm run build    # Generate docs/index.html
npm run preview  # Preview the production build
npx playwright install --with-deps chromium
npm run test:e2e  # Intercepted broker HTTP/WebSockets; never real accounts
```

Commit `docs/index.html` after changes and retain `docs/.nojekyll`. CI rebuilds and rejects distribution drift. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` can select a locally installed Chromium when needed; the default uses Playwright's matching revision.

## Contributing

Keep tests beside the modules they cover under `src/`, using matching `*.test.ts` names. Use descriptive suffixes for separate scenario suites and keep shared synthetic fixtures in the same feature directory. The project-wide architecture checks stay in `src/architecture.test.ts`; browser tests stay in `e2e/`. `npm test` discovers all source tests recursively.

`app/session.ts` composes and disposes services. `broker/` owns credentials and protocol. `market/` owns facts, subscriptions, and bounded session caches. `scanner/` owns rankings and reviews. `robots/` owns research and pure templates. `trading/` alone owns commands, writes, reconciliation, and execution storage. `portfolio/` projects immutable facts. `ui/` contains Preact views and local interaction state.

Pass actual read-only facades to features. Route every broker mutation through `trading/executor.ts`; commit pending intent before sending and await transaction completion. Keep pure numerical helpers independent of ambient time and browser APIs. Import boundaries, cycles, mutation call sites, and kernel purity are checked by `src/architecture.test.ts` in `npm test`.
